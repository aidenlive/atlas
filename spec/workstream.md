# WORKSTREAM: what work is happening, and is it done

> A plan in someone's head leaves when they do.
> A plan in the repository is picked up on Wednesday by whoever shows up.

## What this is

WORKSTREAM governs work in progress: how an initiative is opened, tracked,
verified, and closed. It exists because the three facts anyone needs — what we
are doing, who owns it, whether it is finished — are usually spread across a
chat thread, a spreadsheet, and a memory.

Every initiative is one numbered directory under `work/`, with the same nine
sections in the same order, every time:

| Section | Holds |
|---|---|
| `01_plan` | Objective, scope, milestones |
| `02_tasks` | The task table — the only place status lives |
| `03_requirements` | What must be true when this is done |
| `04_decisions` | Choices made here, and why |
| `05_research` | What was investigated, and what it showed |
| `06_deliverables` | The artifacts this produces |
| `07_validation` | Acceptance criteria and their evidence |
| `08_agents` | Agent assignments, constraints, and handoffs |
| `09_issues` | Problems raised, tracked to closure |

A fixed shape means a person joining on Tuesday and an agent picking the work up
on Wednesday both find the plan in `01_plan/` without asking anyone.

## Invariants

- **W-I1 One home per initiative.** Every initiative is exactly one directory.
  Work spread across two places has no owner and no status.
- **W-I2 Markdown is canonical.** Every fact a human must read is Markdown in the
  repository. Generated views may exist; they never become the original.
- **W-I3 Numbered and immutable.** A workstream's number is assigned once and
  never reused, so a reference to `04` means one thing forever.
- **W-I4 Isolated.** A workstream owns its directory completely. Nothing outside
  it depends on its internal layout.
- **W-I5 Verification is part of the work.** A workstream cannot reach `done`
  without evidence in `07_validation`.
- **W-I6 Every unit has one owner.** Workstreams, tasks, and agent assignments
  each name exactly one accountable principal.

## Rules

- **W-01 Root.** Initiatives live under `work/`, and nowhere else.
- **W-02 Naming.** `NN_kebab-case-slug`, two digits, assigned in order.
- **W-03 Width grows, numbers do not shift.** Past 99, widen to three digits;
  never renumber what exists.
- **W-04 Archive, do not delete.** A closed workstream stays where it is. It is
  the record of why the work says what it says.
- **W-05 Complete skeleton.** All nine sections exist from creation, even when
  empty. An absent section is a question nobody thought to ask.
- **W-06 Deliverables against outputs.** `06_deliverables` holds what this
  initiative promised; scratch output lives elsewhere and is not tracked.
- **W-07 Decisions are local, then promoted.** A choice affecting only this work
  stays in `04_decisions`; one affecting the repository is promoted to an ADR.
- **W-08 Evidence, not assertion.** `07_validation` records how a criterion was
  checked, not that someone believes it was.
- **W-09 Status is a closed enum.** `planned`, `active`, `blocked`, `review`,
  `done`, `cancelled`.
- **W-10 Progress is counted, not felt.** Completion is derived from the task
  table. A percentage nobody can recompute is a mood.
- **W-11 The index is generated.** `work/README.md` and `work/index.yaml` are
  produced from the task tables and never hand-edited.
- **W-12 Stable task IDs.** `T-01` upward, unique within the workstream, never
  reused after removal.
- **W-13 Task status enum.** `todo`, `doing`, `blocked`, `done`. Nothing else.
- **W-14 Assignments are explicit.** Every task names its owner as a principal,
  human or agent.
- **W-15 One orchestrator.** Where several agents work an initiative, exactly one
  principal sequences them.
- **W-16 Handoffs are artifacts.** A handoff is a written note in `08_agents`
  saying what is done, what is in flight, and what is blocked and on whom.
- **W-17 Logs are append-only and dated.** Correct an entry by adding one.
- **W-18 Agent authority is inherited, not invented.** An agent working here holds
  exactly what [ADMIN](admin.md) grants it, and `R-3` still applies.
- **W-19 Derived, never authored.** Any file marked generated is regenerated by a
  command, and a check verifies it is current.
- **W-20 Style is inherited.** Workstream prose follows [WRITING](writing.md),
  like everything else in the repository.
